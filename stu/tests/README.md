# 보안 규칙 테스트

`firestore.rules` 를 고칠 때마다 여기를 돌려 보세요.
"권한이 있어야 하는 사람"과 "없어야 하는 사람"을 **양쪽 다** 확인합니다.

규칙은 한 줄만 잘못 써도 조용히 전부 열리거나 전부 막힙니다.
배포 전에 이 테스트를 통과시키는 것이 실수를 막는 가장 싼 방법입니다.

---

## 준비 (처음 한 번만)

Java 11 이상이 필요합니다. 없으면 [Temurin JDK](https://adoptium.net/) 를 설치하세요.

```
java -version      # 버전이 나오면 OK
```

그다음 이 폴더(`v2/tests`)에서:

```
npm install
```

Firestore 에뮬레이터(약 60MB)는 처음 실행할 때 자동으로 내려받습니다.

---

## 실행

```
npm test
```

Windows 라면 `테스트-실행.bat` 을 더블클릭해도 됩니다.

에뮬레이터가 자동으로 켜지고, 테스트가 끝나면 자동으로 꺼집니다.
실제 Firebase 프로젝트(`sungilnow`)에는 **전혀 접속하지 않습니다.** 데이터가 바뀔 걱정은 없습니다.

통과하면 이렇게 나옵니다.

```
✔ 1. 접근 자체
✔ 2. 글쓰기 권한
✔ 3. 문서 위조
✔ 4. 반별 피드 열람
✔ 5. 중요 알림 확인
✔ 6. 명부 · 권한
✔ 7. 본인 등록
✔ 8. 승인 대기(pending) 제한

# pass 63
# fail 0
```

## ⚠️ 특히 이 테스트를 확인하세요

```
5. 중요 알림 확인
  › 학생이 자기 번호를 빼는 것은 허용된다 (arrayRemove)
```

규칙의 이 줄이 걸려 있습니다.

```
request.resource.data.students == resource.data.students.removeAll([myNumber()])
```

`arrayRemove()` 같은 서버 변환이 규칙 평가 **전에** 적용되어야 이 비교가 성립합니다.
(`createdAt == request.time` 이 동작하는 것과 같은 원리라 정상 동작할 것으로 보지만,
실제 에뮬레이터에서 한 번은 확인하고 배포하시길 권합니다.)

**만약 이 테스트만 실패한다면** — 규칙이 아니라 클라이언트를 바꾸면 됩니다.
`js/db.js` 의 `confirmRead` 를 배열을 직접 계산해 쓰도록 바꾸세요.

```js
// 바꾸기 전
await updateDoc(docRef("class", classKey, id), { students: arrayRemove(number) });

// 바꾼 뒤 (students 는 화면이 이미 들고 있는 현재 배열)
await updateDoc(docRef("class", classKey, id), {
  students: students.filter((n) => n !== number),
});
```

다만 이렇게 하면 여러 학생이 **동시에** 확인 버튼을 누를 때 마지막 쓰기가
앞의 것을 덮어쓸 수 있습니다. 되도록 `arrayRemove` 를 유지하세요.

## 등장인물

테스트 안에서 쓰는 가상의 명부입니다. 실제 계정과 무관합니다.

| 계정 | 역할 | 반 | 번호 | 권한 |
|---|---|---|---|---|
| june@ | 교사 | 2-3 | — | 총관리자, 담임 |
| admin@ | 교사 | — | — | 관리자 |
| hong@ | 교사 | 1-1 | — | 담임 |
| lead@ | 학생 | 2-3 | 1 | 반장 |
| s14@ | 학생 | 2-3 | 14 | — |
| s20@ | 학생 | 2-3 | 20 | — |
| other@ | 학생 | 1-1 | 5 | — |
| ghost@ | 학교 계정이지만 **명부에 없음** | | | |
| someone@gmail.com | **외부 구글 계정** | | | |

| pend@ | 교사 신청 후 **승인 대기** | | | |

`ghost@` 는 본인 등록 테스트에도 쓰입니다. 외부 계정과 미등록 계정을 막는 것이
v1 의 가장 큰 구멍이었고, `pend@` 는 v2.1 에서 학생이 교사로 잠입하지 못하게
막는지를 확인합니다.

**본인 등록에서 반드시 통과해야 하는 것** — 이름 앞에 ★ 가 붙은 테스트들입니다.
권한(`privilege`)을 스스로 주는 것, 교사로 즉시 활성화되는 것, 남의 문서를
만드는 것이 모두 막혀야 합니다. 하나라도 실패하면 배포하지 마세요.

## 규칙을 고칠 때

1. `../firestore.rules` 수정
2. `npm test`
3. 통과하면 Firebase 콘솔 → Firestore → 규칙에 붙여넣고 게시

새 기능을 넣어 규칙을 늘렸다면, **거부되어야 하는 경우**를 먼저 테스트에 추가하세요.
허용 테스트만 늘리면 열려 있는 문을 못 봅니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `rules.test.mjs` | 테스트 본문. `../firestore.rules` 를 읽어 에뮬레이터에 올립니다 |
| `firebase.json` | 에뮬레이터 설정 (포트 8080) |
| `emulator-boot.rules` | 에뮬레이터를 켜기 위한 자리표시자. 테스트에는 쓰이지 않습니다 |
